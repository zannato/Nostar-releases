Nostar 1.0.8

Sincronizzazione multi-Mac delle impostazioni di progetto tramite cloud, dashboard cliente con preview ordinate per vista del wizard, e default di ordinamento tabella allineato al flusso di scatto reale (ultimi prodotti aggiunti per primi).

Novità

  • Session sharing cloud delle impostazioni progetto: il bundle progetto sul cloud ora trasporta l'intero ProjectSettings (background, crop, color tag, flag QC, naming metadata). Un secondo Mac che apre lo stesso progetto eredita esattamente i parametri configurati dal primo, senza dover riconfigurare il QC manualmente.
  • Dashboard cliente: preview ordinate per vista: nella view prodotto del dashboard web le miniature seguono ora la sequenza definita nel wizard (view_requirements.sort_order) invece di un ordine implicito per data di upload. La caption mostra SKU · Nome vista (es. "ABC-123 · Fronte") al posto del solo suffix tecnico.
  • Tabella prodotti: ordinamento per data di creazione: il default di ordinamento è ora Creazione · più recenti prima, allineato al workflow di shooting reale dove i prodotti appena fotografati devono essere immediatamente visibili in cima. Il menu di sort nel topbar è stato riorganizzato; ogni criterio applica il proprio ordinamento di default più sensato (es. data → decrescente, nome → crescente).
  • Wizard QC: snapshot dinamico al posto dei default: quando crei un nuovo progetto, le impostazioni QC catturate dallo Step 4 riflettono lo stato corrente dei pannelli Background/Crop/Tag Colore, non più valori hardcoded. Questo elimina il caso in cui un progetto creato dopo aver personalizzato i settings globali partiva comunque dai default.
  • Catalog import lookup-first esteso: estensione del flusso lookup-first introdotto in 1.0.7 con copertura aggiuntiva di sorgenti categorie e nuove fixture di test deterministici sul roundtrip completo.

Note tecniche

Lato server (Cloudflare Worker): nuova migration 0018_project_settings_json aggiunge la colonna settings_json a project_settings, gestita con UPSERT last-write-wins via COALESCE. L'endpoint /api/sync/project-bundle accetta e persiste body.project.settings come blob JSON opaco; backward-compatible con client pre-0018 (campo omesso → no-op).

Lato app: ProjectConfigDraft.toProjectSettings() ora invoca ProjectSettings.fromCurrent() sui singleton runtime invece di costruire BackgroundSnapshot.defaults/FileCropSnapshot.defaults hardcoded. Per progetti cloud, ProjectConfigDraft.applyCloudBundle() popola i flag QC dal bundle remoto se presente. CloudProjectBundlePayload/CloudProjectBundleResponse hanno il nuovo campo opzionale settings: ProjectSettings?, codifica round-trip coperta da CloudPayloadCodingTests + CategoryTemplateDatabaseTests (3 nuovi test, di cui 2 per backward compat con bundle senza settings).

Dashboard web (dashboard/src/routes/d/[linkId]/+page.svelte): previewsByProduct ora effettua solo grouping per product_id senza pre-sort; l'ordinamento canonico è centralizzato in previewSlotsFor via la nuova helper viewRequirementsFor(product) che include sia viste required che opzionali, ordinate per sort_order. La caption del figcaption mostra ora {productDetail.sku} · {slot.viewLabel}.
